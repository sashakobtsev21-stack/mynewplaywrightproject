01What the AI layer does now

Eleven capabilities, each engineered for real traffic rather than a demo. File references point at src/ai/.

Prompts as code

Every prompt is a versioned <name>.v<N>.md with a declared input/output contract; the loader enforces it and substitutes in a single pass (no placeholder smuggling).

prompts/ · prompt-loader.ts

Structured outputs

Model replies are zod-validated: a strict schema, a looser fallback, and recovery for JSON truncated at max_tokens. Nothing unvalidated reaches a test.

structured.ts · schemas.ts

Retrieval grounding (RAG)

The test generator grounds each draft in the existing specs most similar to the requirement, ranked by BM25 over the spec corpus — lexical, deterministic, no vector DB.

retrieval/bm25.ts

Agentic tool-use

The failure analyzer also runs as a tool-use loop: the model investigates with list_dir / read_file / grep / view_screenshot, every path sandboxed to the repo root, every tool input zod-validated.

agentic-analyzer.ts

Provider-agnostic

Text helpers go through an LLMProvider interface: Anthropic, or any OpenAI-compatible endpoint (OpenAI, local Ollama / LM Studio) via fetch — switched by LLM_PROVIDER.

providers/

Reliability

One entry point for every call (callClaude) with exponential backoff + jitter, retrying only on rate limits, 5xx, and transient connection errors.

anthropic-client.ts

Observability

Each call writes a JSONL trace (latency, tokens, cost, provider, prompt version) and can also ship as an OpenTelemetry span over OTLP/HTTP to any collector (Jaeger, Tempo, Honeycomb).

observability.ts · exporters/

Cost awareness

Token-based cost per call, a per-developer budget, and npm run ai:budget to total spend across providers from the trace log (local endpoints billed at $0).

budget.ts · observability.ts

Safety

Untrusted inputs (a requirement, a failure's context + screenshot) are fenced as <untrusted_data> with an injection heuristic; secrets/PII are redacted before any trace is persisted.

redaction.ts

Evals & release gate

A suite scores each helper and an LLM-as-judge (haiku) grades analysis quality 1–5; a gate fails CI when thresholds aren't cleared. Runs offline (deterministic) on every PR.

evals/ · gate.ts · judge.ts

Agent team

The repo is developed with eight curated Claude Code subagents (prompt-engineer, AI-safety, code-reviewer, …), a project-specific subset of a larger agent library.

.claude/agents/

A clear position on AI in QA

Generated tests carry false confidence; failure analysis is a hypothesis, not a verdict. Validation, traces, and evals exist so output is trusted as far as it's earned — no further.
