AI-ассистированная автоматизация тестов

Это набор автотестов на Playwright + TypeScript, поверх которого построен «умный» слой на базе модели Claude (Anthropic). Главное здесь — не сами тесты, а то, как по-взрослому сделан AI-слой: с проверками, защитой, метриками и оценкой качества, а не «просто дёрнуть API». Этот документ объясняет всё простым языком — для тех, кто не в теме.

00Если совсем коротко

Есть приложение (сайт бронирования) — его надо тестировать. Тесты написаны на Playwright. А ещё к проекту прикручён слой искусственного интеллекта: он помогает писать тесты, разбирать падения и придумывать тестовые данные. Этот слой сделан так, чтобы ему можно было доверять под реальной нагрузкой — отсюда защита, проверки, учёт денег и автоматическая оценка качества. Именно эта инженерия и есть портфолио под вакансию AI Engineer.

01Словарь для чайников

Короткие объяснения терминов, которые встретятся ниже.

LLM (языковая модель)

ИИ, который понимает и пишет текст — например Claude или GPT. Ему дают задание текстом, он отвечает текстом.

Промпт

Инструкция модели текстом. В проекте промпты лежат отдельными версионированными файлами — как код, который можно ревьюить и менять.

Токены и стоимость

Модель считает текст в «токенах», и за них платят деньги. Проект считает стоимость каждого вызова и держит бюджет.

Prompt-injection

Атака: во входных данных прячут команду вроде «забудь инструкции и сделай другое». Защита — чётко отделять «данные» от «инструкций».

PII и секреты

Личные данные (почта, телефон) и ключи доступа. Их нужно вычищать из логов, чтобы они никуда не утекли.

Структурированный вывод

Заставляем модель вернуть строгий JSON и проверяем его схемой (zod). Невалидное до теста не доходит.

Агент / tool-use

Модель не отвечает за один проход, а в цикле сама пользуется инструментами: открыть файл, поискать по коду, посмотреть скриншот.

RAG (retrieval)

Перед генерацией находим в проекте самые похожие примеры и подкладываем их модели — чтобы «заземлить» её и получить релевантный ответ.

Эмбеддинги

Перевод смысла текста в набор чисел. Позволяет искать «по смыслу», а не по точным словам.

Провайдер

Поставщик модели (Anthropic, OpenAI, локальный Ollama…). Проект умеет переключаться между ними одной настройкой.

Трейс / наблюдаемость

Запись о каждом вызове: сколько длился, сколько токенов и денег. Можно отправлять во внешние системы (Jaeger, Langfuse).

Eval + гейт

Автотесты качества ИИ. «Гейт» — это порог: если качество просело, сборка (CI) падает и плохой код не проходит.

02Что умеет AI-слой (простыми словами)

Двенадцать возможностей. В скобках — где это лежит в коде, в папке src/ai/.

Промпты как код

Каждый промпт — отдельный файл с версией и контрактом «что на вход / что на выход». Менять и проверять их можно как обычный код.

prompts/ · prompt-loader.ts

Проверка ответа модели

Ответ модели разбирается и проверяется строгой схемой; есть мягкий запасной вариант и починка «обрезанного» JSON. В тест не попадёт ничего непроверенного.

structured.ts · schemas.ts

RAG-заземление

Генератор тестов подбирает самые похожие существующие тесты (по умолчанию алгоритмом BM25; опционально — «по смыслу» через эмбеддинги) и показывает их модели как образец.

retrieval/

Агент с инструментами

Анализатор падений умеет сам исследовать проект: открыть папку, прочитать файл, поискать по коду, посмотреть скриншот. Все пути ограничены корнем репозитория (песочница).

agentic-analyzer.ts

Не привязан к вендору

Текстовые помощники ходят через единый интерфейс: Anthropic или любой OpenAI-совместимый сервис (OpenAI, локальный Ollama) — переключается настройкой LLM_PROVIDER.

providers/

Надёжность

Один общий путь для всех вызовов: при сбое — повтор с нарастающей паузой, но только на «временных» ошибках (лимиты, 5xx, обрыв сети).

anthropic-client.ts

Наблюдаемость

Каждый вызов пишет строку-трейс (время, токены, стоимость, провайдер) и может уходить как OpenTelemetry-спан или в Langfuse — в любую систему мониторинга.

observability.ts · exporters/

Учёт денег

Стоимость считается на каждый вызов; есть личный бюджет и команда npm run ai:budget, которая суммирует траты (локальные модели — $0).

budget.ts

Безопасность

Недоверенный ввод (требование, контекст падения, скриншот) огораживается как «данные», работает эвристика на prompt-injection, а секреты/PII вычищаются до записи в трейс.

redaction.ts

Оценка качества + гейт

Набор проверяет каждого помощника, а LLM-судья (дешёвая модель) ставит анализу оценку 1–5. Если средний балл/проходимость ниже порога — CI падает. В CI идёт офлайн на каждый PR.

evals/ · gate.ts · judge.ts

Команда агентов

Проект разрабатывается восемью кураторскими Claude Code субагентами (prompt-engineer, AI-safety, ревьюер кода и др.) — выборка из большой библиотеки агентов.

.claude/agents/

Честная позиция про AI в QA

Сгенерированный тест даёт ложную уверенность; анализ падения — гипотеза, а не вердикт. Проверки, трейсы и evals существуют, чтобы доверять выводу ровно настолько, насколько он это заслужил.

03Как работает один вызов

Все помощники идут одним путём — надёжность, деньги, безопасность и метрики живут в одном месте. 

требование ──▶ RAG: найти похожие спеки ──▶ собрать промпт из файла
                                                  (недоверенный ввод огорожен)
                                                        │
                                                        ▼
                                          провайдер модели (.complete)
                                   Anthropic  ◀──┴──▶  OpenAI-совместимый
                                                        │
                          callClaude(): пауза+джиттер, повтор только на временных ошибках
                                                        │
                        ┌───────────────────────────────┼───────────────┐
                        ▼                                ▼               ▼
                проверка ответа (zod)        запись трейса (без секретов)  экспорт трейса
                строгая → мягкая → починка   logs/ai-traces.jsonl          OTLP / Langfuse
                        │                                │
                        ▼                                ▼
                 черновик / данные            npm run ai:budget · Jaeger / Langfuse

  анализатор-агент: цикл { модель → вызов инструмента → результат (в песочнице) }
  evals: оценить помощников → судья-LLM (1–5) → сверка с порогом → CI падает, если ниже
