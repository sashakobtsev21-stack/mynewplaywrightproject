# AI features

Three small helpers wired on top of the [Anthropic API](https://docs.anthropic.com/).
All three are **optional** — without `ANTHROPIC_API_KEY` set, the rest of the
test suite is unaffected.

> **Why bother?** Plenty of QA work is mechanical (drafting new specs, staring
> at a stack trace at 23:00). Claude is decent at the boring parts. It is not
> decent at owning quality — that's still on the QA. Treat the output as a
> first draft, not a verdict.

## Setup

```bash
echo "ANTHROPIC_API_KEY=sk-ant-..." >> .env
# Optional: override model. Default is claude-sonnet-4-5.
# echo "AI_MODEL=claude-haiku-4-5" >> .env
```

The key is consumed exclusively from `process.env.ANTHROPIC_API_KEY` via
`src/config/env.ts`. CI reads it from `secrets.ANTHROPIC_API_KEY` (you don't
have to set it — the suite runs without AI just fine).

### Approximate cost

Sonnet 4.5 pricing at the time of writing, rough per-call estimates:

| Operation                            | Cost / call    |
| ------------------------------------ | -------------- |
| Test generation (1 spec)             | $0.01 – $0.03  |
| Failure analysis (text + screenshot) | $0.02 – $0.05  |
| Data generation (5 records)          | $0.005         |

Cache hits in the data generator are free. Run the full test suite a few
hundred times — AI helpers stay below a few dollars a month.

## 1. Test Generator

`src/ai/test-generator.ts` + CLI `scripts/generate-test.ts`.

Take a plain-English requirement, get back a Playwright `.spec.ts` draft that
already knows about the project's POMs and API clients.

### Use

```bash
npm run ai:generate-test -- \
  --requirement "User can mark a room as favourite from the home page" \
  --type ui
```

Output goes to `tests/_generated/<slug>.spec.ts`. The first line is always:

```ts
// [AI-DRAFT] generated by scripts/generate-test.ts — review before committing
```

The `_generated/` folder is **git-ignored** by default. You're expected to
read the draft, fix any selectors Claude guessed at, move it under the
appropriate folder (`regression/`, `smoke/`, etc.), and then commit.

### What goes into the prompt

The generator scans the repo and includes:

- list of files under `src/pages/`
- list of files under `src/api/clients/`
- one full example spec for the chosen `--type` (UI or API), as a style reference
- the requirement verbatim

It does **not** include the source of every POM — that would blow the context
window for not much win. Claude is good at inferring from the filename + the
example spec.

### What it does NOT do

- It does not auto-commit. Ever.
- It does not run the generated test (no way for it to know if the selectors
  match reality without browsing).
- It does not invent new POMs or clients. Prompt explicitly forbids that.

## 2. Failure Analyzer

`src/ai/failure-analyzer.ts` + CLI `scripts/analyze-failure.ts`.

After a test fails locally or in CI, drop the trace folder on it and get a
short markdown analysis: hypothesis + concrete next steps.

### Use

```bash
# Folder works — Playwright already extracted error-context.md + screenshot
npm run ai:analyze -- --trace test-results/regression-booking-flow-chromium

# Pointing at the trace.zip also works (we use the parent folder)
npm run ai:analyze -- --trace test-results/<...>/trace.zip --spec tests/regression/ui/booking-flow.spec.ts
```

Output is also written to `ai-analysis/<timestamp>-<slug>.md` for the record.

### What goes in

- `error-context.md` (Playwright writes this for every failure — it's a DOM
  snapshot at the moment of failure)
- the failure screenshot, attached as a base64 `image` content block
- optionally, the spec source via `--spec`

### What it does NOT do

- It does NOT parse `trace.zip` itself. That would need `yauzl`/`adm-zip`
  and a chunk of code I haven't written. The folder Playwright already
  extracts to is enough for a useful first pass.
- It does not re-run the failing test. It just looks at the artefacts.

### Without an API key

You still get a structured local dump (`error-context.md` content, screenshot
path) — handy when you just want to peek without burning tokens.

## 3. Data Generator

`src/ai/data-generator.ts`. Imported programmatically — there's no CLI.

A drop-in for `bookingFactory()` / `guestFactory()` when you want data that's
more contextual than what faker produces.

### Use

```ts
import { aiDataGenerator } from '../../src/ai/data-generator';

test('booking for a business guest staying long-term', async ({ bookingClient }) => {
  const [payload] = await aiDataGenerator.generate('booking', {
    context: 'international business guest, 10-night stay, paid in advance',
    count: 1,
  });
  const created = await bookingClient.create(payload);
  // ...
});
```

### Caching

Results are cached on disk at `cache/ai-data/<sha1>.json`. The cache key is
`sha1(kind | context | count)`. Identical calls return cached results instantly
and cost nothing.

To force a refresh, delete the cache file (or the whole directory).

### Fallback chain

1. No `ANTHROPIC_API_KEY` → faker (silent, logged at debug level).
2. Cache hit → cached value.
3. Claude call fails (network, rate limit, parse error) → faker, logged at warn.

This means **tests never break because of the AI helper**. If Claude is having
a bad day, you get faker data and a yellow log line, not a red CI.

## Limits and gotchas

- **No streaming.** Outputs are small (≤ 2K tokens) — not worth the extra
  plumbing.
- **No retries.** A single failure falls back where possible (data generator)
  or surfaces to the user (generator/analyzer).
- **Trace.zip is opaque.** If you really need step-by-step actions from a
  trace, use `npx playwright show-trace` and copy details by hand for now.
- **Model drift.** If Anthropic deprecates `claude-sonnet-4-5`, point
  `AI_MODEL` at the next one. Schemas of input/output don't depend on the
  specific model.
